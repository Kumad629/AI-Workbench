## Gemini 整段正文触发隐藏过滤（扩展 v0.12.7）

本轮已获用户 Chrome 实测确认（2026-10-19）：扩展 v0.12.7 命中唯一 Gemini 原文读取，约 3.5 秒收到首批正文、约 19.4 秒完成（含网页生成与稳定判断），共 1626 字符，无连接错误；历史同步成功补回 1 条旧失败回答，另有 1 轮差异按规则保留本地版本。具体隐藏样式来源未证明，不归因给 Voyager 或 Figma，当前可继续使用 Chrome。完整验收见 DEVELOPMENT_LOG.zh-CN.md 第 70 节。


第二轮现场诊断：v0.12.6 有六问六答、发送按钮只点击一次、唯一新回答和完成依据均正常；原始正文 1409 字但读取 0 字，p、h3、ol 等均进入 hidden-css 分支，voyagerHighlights=0。用户明确没有开启翻译。因此上轮高亮兼容未命中本次故障，不再将原因归给高亮、翻译或 Voyager。旧诊断将隐藏属性与 CSS 状态合并为一个原因，尚不能证明具体是哪项页面改动导致隐藏。

本轮保留常规可见正文读取。仅当它完全为空，且本轮 model-response 内有唯一、常规可读的 message-content / 原生 markdown 正文结构时，补读该 markdown 的源 DOM，忽略外部样式表对子节点的隐藏。仍遵守 hidden 属性、内联 display:none / visibility:hidden/collapse、aria-hidden 和思考/操作控件排除；不读整页、不选歧义副本、不改变 ChatGPT 的读取策略。历史同步和实时接收共用该逻辑。只读结构，不修改原网页、不克隆 Angular 节点、不调用额外模型接口。

诊断新增 readMode（visible-dom / gemini-source-dom）、sourceBlockCandidates；被过滤项同时报告 display、visibility、hiddenAttribute、inlineDisplay、inlineVisibility，仍有采样上限且不含正文。借鉴并独立实现源正文读取方式，参考 [Voyager 正文提取器](https://github.com/Nagi-ovo/voyager/blob/main/src/features/export/services/DOMContentExtractor.ts)；没有复制其实现或加入依赖。

使用：桌面继续 v0.18.4。在 Chrome 重新加载工作台扩展至 v0.12.7，从原 Gemini 对话重新连接，然后在工作台对应的 Gemini 网页聊天点击「仅同步已加载」，尝试补回已有失败回答，不重新发送原问题。Voyager 可以保留。若这最后一轮实页仍失败，按用户原计划改在 Edge 登录 Gemini，不继续追加试探性 Chrome 修复。

## Gemini Voyager 高亮兼容（扩展 v0.12.7）

用户确认 Chrome 长期启用 Gemini Voyager。核对 Voyager 官方源码与本机公开扩展代码后，发现高亮功能把正文文字包在带 role="button"、data-gv-highlight-id 的 mark.gv-highlight-mark 中；工作台旧规则把其当作操作控件整段丢弃。现仅对 Gemini 中这个确切的行内高亮标记保留正文，真实 button、其他 role="button"、隐藏分支、思考区和导出控件仍过滤。不修改或停用 Voyager，不增加权限或依赖。

来源：[Voyager 高亮实现](https://github.com/Nagi-ovo/voyager/blob/main/src/pages/content/highlight/HighlightMarks.ts)。这是可复现的兼容问题，但尚未直接观察失败的 Chrome DOM，不能据此断言本次全部读空只由高亮造成。诊断 latestReply 和 lastSendAttempt.receive.answer 增加 voyagerHighlights / voyagerHighlightCharacters、最多八项 rejected（标签、原因、字符数），最多采样 160 个后代元素并标注截断；不包含正文、按钮文字或高亮 ID。若仍失败，用这些字段定位用户限定两轮中的最后一轮。

在 Chrome 扩展管理页重新加载 AI Workbench 至 v0.12.6，保持 Voyager 启用，从 Gemini 原网页重新连接；对已失败的回答先点工作台对应网页聊天「仅同步已加载」，无需重发原问题。桌面继续 v0.18.4。

## Gemini 已完成却接收为空

本次旧任务的英文中止错误确认为 12 分钟自动超时。新版将其显示为中文接收超时，并区分主动停止；通过源会话、群聊、任务及时间证据确认的旧自动超时，可在历史可靠匹配后补回原消息，保留原 ID 和源记录的失败审计，不自动重发。你的这次真实数据已做只读内存预演，确认可补回一条；实际数据尚未修改。

完全退出并重开工作台至 v0.18.4，在 Gemini 的 Chrome 重新加载扩展 v0.12.6，回原网页重新连接，再在工作台 Gemini 网页聊天点击「仅同步已加载」。随后回群聊查看「已补回网页回答 · 未重新发送问题」，不需要重发原问题。

## 网页账号加入群聊

已修正「网页已连接但加入按钮灰色」：网页输入区可用时，即使初始历史读取失败或为空，也可在加入时建立本地会话记录，不会将未读取的历史标为已同步。灰色按钮会显示草稿、同步中、被其他对话占用等具体原因。升级后重开工作台并重新连接网页；扩展需为 v0.12.6，已是此版本则无需更新。

1. 完全退出并重开工作台，确认桌面 v0.18.4；在 Gemini 所在 Chrome、ChatGPT 所在浏览器的扩展管理页重新加载 AI Workbench，确认扩展 v0.12.6。无需清除已有聊天。
2. 分别打开两家的一条专用网页会话，在各自标签页点击扩展的连接按钮；保留原网页和连接页，等待已加载历史同步结束。
3. 回工作台切到「群聊」，点击「选择参与模型」或右上角面板按钮，在右侧选择「添加网页账号成员」，将已连接的 Gemini、ChatGPT 分别加入。元宝、豆包也可通过相同入口添加。
4. 不加 @ 时发给所有选中成员；输入 @Gemini 或 @ChatGPT 后加空格可定向追问，也可用「发送给」选择。需要转交另一模型的观点时，点击那条回答的「引用」，再选择目标成员并发送。

无需 API Key，可与已有 API 成员混用。网页只接收本次问题（含明确选择的引用），不接收工作台拼接的其他模型历史；原网页自身历史照常保留。因此「携带历史」只控制 API 成员，不清空网页历史。一条专用网页只供一条工作台对话使用；需要另开群聊时，请先另建网页会话再添加。断线、切错网页和停止接收不会自动重发；停止接收也不会撤回已发送问题或中断网页生成。

网页成员每次最多 100,000 字符（桌面 v0.18.5 起，问题、文件、链接资料和引用合计），暂只发送文字；添加文件会先提取为文字，过长资料需要拆分。Gemini 双输入框问题已加入富文本优先识别和无正文结构诊断；遇到两个真正独立的输入区仍拒绝发送。构建、隔离群聊链路与回归测试已验证，用户账号真实页面仍需更新扩展后试用。详细记录见 [网页成员说明](WEB_MEMBERS.zh-CN.md)。

## 读取问题中的网页 / PDF 链接

普通 API 聊天（例如 DeepSeek）输入区默认勾选「读取链接」。直接把公开网页或 PDF 网址贴入问题并发送，工作台先下载、提取正文，再将带来源网址、读取时间和范围的资料发给模型。最多三个链接；只有问题本身的链接会触发，附件中的链接和旧聊天不会被自动遍历。不需要搜索 API Key，不会做全网搜索。

读取中可取消。失败时保留草稿，不向模型发送这轮问题；可重试、复制正文、添加下载的 PDF，或关闭「读取链接」只发送原文字。发送成功后，资料在消息下折叠展示，点击查看；部分读取会在折叠标题中继续提示，避免误认为全文。资料随本条消息保存、携带历史、复制和导出。每轮重新读取，不缓存旧网页冒充新数据。

链接单个下载最多 20 MiB，总正文预算最多约 85,000 字符，由来源均分；超过预算只发送明确标注的部分内容。PDF 最多处理 500 页，提取文字与页码，不提供 OCR 或准确表格版式还原。登录、验证码、动态网页、网站限流可能读不到，不能绕过网站限制。此开关用于 API 单聊/群聊；网页账号聊天仍沿用原网页能力。浏览器扩展无需更新。

已使用独立临时环境实测用户截图中的 SEC 财报网页、51 页财报演示 PDF，以及 W3C 公开 PDF 样例，均读到文字；两份较长材料触发部分读取标注。未向真实模型发送测试问题。实现和验证详见 [链接读取说明](LINK_READER.zh-CN.md)。

## 添加文件

点击聊天输入框旁的「添加文件」，或把文件拖到输入框内。选择后可预览提取内容、移除，也可不填写额外文字直接发送。

| 类型 | 支持格式 |
| --- | --- |
| 文字与 Markdown | .txt / .md / .markdown / .mdown / .csv / .tsv |
| Word | .doc / .docx |
| Excel | .xls / .xlsx |
| PowerPoint | .ppt / .pptx |
| PDF | .pdf（含文字层） |

每次最多 5 个文件；文字文件单个最多 1 MiB，Office / PDF 文件单个最多 10 MiB。TXT / CSV / TSV 支持 UTF-8、带 BOM 的 UTF-16，以及 GB18030 编码回退；MD 使用 UTF-8。读取在本机完成，发送的是提取后的文字与表格，不是原始 Office 文件；原始二进制不存入聊天。文件内容随消息保存，后续上下文、复制及 Markdown / JSON 导出保留正文。不会自动安装或执行其中的 Skill、脚本、宏或公式。

普通 API 聊天和网页聊天统一最多 100,000 字符（含问题、文件、链接资料和引用），沿用现有文字发送通道。超限会提示，不静默截断。三种外观、API 单聊/群聊和网页聊天均有入口，原有 @ 定向规则不变。

Word 读取正文与常见附属文字；Excel 按工作表整理单元格，公式使用文件已有缓存结果，不重新计算；PowerPoint 按幻灯片顺序读取文字与备注。图片、图表、扫描件文字和原始版式不在本次范围内，复杂表格请核对预览。加密、损坏、无可读文字或超过解析限制的文件会明确提示。

完全退出并重开工作台即可使用，本次无需更新浏览器扩展。读取范围、依赖来源与验证记录见 [文件读取说明](FILE_READERS.zh-CN.md)。

## 语音输入：工作台录音与本地识别

1. 点击输入框旁的「语音输入」→「开始录音」。
2. 默认开启「说完自动填入」：说完后安静约 2 秒，自动结束录音并在本机识别；也可点击「完成录音」立即识别。
3. 文字填入原草稿的光标 / 选中位置，检查后手动发送。需要边想边说、较长停顿或先试听时，关闭「说完自动填入」，恢复手动完成、试听和识别。此偏好会记住。

自动结束依据麦克风音量判断，环境持续嘈杂时可手动完成；连续 15 秒未检测到清晰说话声会停止并提示，不会自动识别空录音。识别失败保留录音供重试，模型未就绪时保留录音等待手动识别。

每次最多两分钟；取消、关闭或切换会话会停止录音。识别失败保留本次录音供重试；关闭面板会清理本次录音。录音仅在内存中，不写入聊天记录、不上传到语音服务。模型在独立 CPU 进程加载，完成、取消或超时后退出，释放识别内存。如果识别期间原草稿发生变化，会保留结果供手动追加，不覆盖新草稿。

已在本机准备 SenseVoice int8 中文 / 多语言模型。模型与词表 **239,549,735 字节**，Windows CPU 运行组件 **23,514,467 字节**，合计约 **263 MB（251 MiB）**。不需要语音 API、Python、PyTorch、CUDA 或显卡。模型就绪后录音和识别可离线使用；Windows 本身仍需允许工作台访问麦克风。

模型位于项目的 local-models/sensevoice，可在语音面板删除，之后按需重新下载。首次在其他电脑使用时，面板提供约 240 MB 下载；主站为 Hugging Face，主站不可达时回退到 HF 镜像，固定版本及 SHA-256 校验通过后才使用。取消下载会删除未完成文件，已校验文件保留以免重复下载。可通过 AI_WORKBENCH_VOICE_MODEL_DIR 指定模型保存位置。依赖按 package-lock 安装；模型不包含在源码或聊天 JSON 备份中。

验证：浏览器测试音源覆盖实际录音、试听、取消和草稿保护；作者公开中文样例已通过真正的本地模型及 Electron 进程完整识别、草稿回填。约 5.6 秒样例一次识别约 3.8～4.2 秒，此结果不代表任意长度、口音或噪声环境的性能。用户已确认自己的麦克风录音与识别可用；新版自动结束已通过公开音频测试，不同噪声环境仍可能需要手动完成。识别可能有错字，发送前应检查。组件来源见 [本地语音依赖说明](THIRD_PARTY_VOICE.md)。

## 已实现

- 单聊中切换模型，带入当前分支的文本历史；可选择只发送本次问题。
- 多连接群聊并发回答；每个连接独立停止、失败、重试。重试保留原答案。
- 群聊默认使用公共提问和各模型自己的历史答案；通过发送目标或 `@连接名称 ` 单独追问。引用别人的回答会显式附加原文。
- 每条 API 回答记录连接、供应商、模型、状态、用量（服务返回时）和实际发送的上下文。
- 从已完成消息创建独立分支。
- 自动保存完整会话；重命名、文件夹、标签、全文搜索、归档和恢复。
- 左侧会话支持右键或「⋯」菜单：置顶 / 取消置顶、重命名、移动文件夹、分享、导出、归档 / 恢复、删除；有来源链接时可打开原网页。
- 分享提供 Markdown 预览、复制与文件导出，默认排除私人笔记和精选；不生成公开链接。删除前会显示消息及关联精选的范围，删除仅限本机，不修改网站原记录。
- 收藏完整回答或选中文字，附加标签与笔记，并回到原消息。
- 导出 Markdown 或 AI Workbench JSON；JSON 可导入会话与精选，导入不会带入密钥。
- 保存 Grok 等外部对话：粘贴原文、填写来源链接和“我的想法 / 项目草案”。原文按整体保留，不假装自动还原说话角色。
- 本地 SQLite 持久化；密钥使用 Electron safeStorage 的系统加密能力后保存。没有可用加密能力时拒绝保存密钥。

## 真实模型连接

在“连接与设置”中添加 DeepSeek API Key，模型 ID 可修改为你账号实际可用的型号。支持 Gemini 的兼容接口预设及自定义 OpenAI 兼容 Chat Completions 接口。基础地址由适配器自动追加 `/chat/completions`。

**自动化验收使用本地 HTTP 测试服务，未使用你的真实密钥。用户已实际试用 DeepSeek；其他供应商的真实接入仍需分别验证。首次配置时，请在应用设置页填写自己的密钥。**

API 接口与网页产品是不同的连接：
- 尚未实现元宝、豆包、ChatGPT、Gemini 四家网页账号的一键群发。
- 已支持主动读取当前 X 内 Grok 对话；尚未实现全量账号历史自动同步、独立 grok.com 适配或第三方导出格式解析。也支持粘贴原文及导入本应用自己的 JSON。
- 尚未实现 Claude Code + DeepSeek 的工具桥接，也未新增 Claude 模型要求。
- WorkBuddy、豆包工作保留为后续扩展。
- API 聊天当前处理文本；元宝、豆包网页聊天支持图片。文档附件、跨模型自动讨论、自动项目草案生成和安装包尚未实现。

## Grok 对话沉淀

1. 点击左侧“保存外部对话”。
2. 粘贴有价值的讨论原文，保留原有提问和回答标记。
3. 保存 X 原帖、Grok 对话的链接，以及讨论产生的项目想法。
4. 之后可以搜索原文、收藏片段、补充笔记，或导出带来源的 Markdown。
5. 如选择 API 连接继续讨论并勾选“携带历史”，导入原文会明确作为用户提供的外部资料发送。

仅粘贴和保存不调用云端模型；来源链接只存储，不自动访问。

## 本地数据

默认保存位置：

```text
%APPDATA%\AI-Workbench\workbench.sqlite
```

聊天数据独立于源码目录；修改 `AI-Workspace` 的名称不会改变数据位置。设置页显示实际路径。密钥经系统加密保存，拷到其他系统或用户下可能无法解密，届时需重新填写。

使用 JSON 会话导出进行内容备份；如复制整个数据库目录，请先完全退出应用，并一起保留同目录内的 SQLite 相关文件。
