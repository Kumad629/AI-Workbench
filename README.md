## ChatGPT / Gemini 网页文字聊天（首版）

1. 完全退出并重开工作台，确认 v0.14.0；在 Edge / Chrome 的扩展管理页重新加载 AI Workbench，确认扩展 v0.12.0。
2. 分别登录 chatgpt.com 和 gemini.google.com/app，打开各自的一条专用对话；先处理已有草稿、附件及正在生成的回答。
3. 在对应原网页点击扩展 →「连接ChatGPT网页聊天」或「连接Gemini网页聊天」，保留该原网页与连接页。
4. 回工作台「网页账号」→ 对应的「进入 … 网页聊天」，等待已加载历史同步结束，再输入文字并发送。

每个平台单独绑定、接收和保存；两者可同时连接。本阶段只做独立网页文字聊天，尚未接入四家网页群发、@ 定向追问和显式转交另一模型回答。网页已有模型设置、历史和额度照常沿用；工作台不会自动把其他模型的回答加入问题。支持新建对话首次生成网址后继续接收、流式保存、停止接收、重新连接及 Markdown / JSON 导出。断线或重启不会自动重发，未识别唯一发送按钮时保留草稿。

首版 ChatGPT / Gemini 聊天只同步当前已加载的历史，不自动扫描合并，不支持从工作台发送图片。Gemini 原「加载并读取历史对话」存档入口仍保留，和实时聊天同步是两条入口。ChatGPT 先支持普通 /c/ 对话，暂不接入自定义 GPT / 项目路径；Gemini 先支持 /app/ 路径，不向只读分享页发消息。

已在隔离 Electron 数据和测试网页中验证实际本地连接链路；还未对用户登录账号发送真实消息，首次真实页面试用如有错误，请复制连接页诊断。实现及边界见 [ChatGPT / Gemini 适配记录](STANDARD_CHAT_NOTES.zh-CN.md)。

## YouTube 视频提问栏存档

1. 在 Chrome / Edge 中打开视频，展开右侧「提问 / Ask」面板，等待回复完成。
2. 点击 AI Workbench 扩展 →「加载并读取历史对话」。只滚动提问栏，最长约 3 分钟；也可选择「读取提问栏选中文字 / 已加载内容」。
3. 核对预览的首条提问、末条回答与读取范围 →「保存到 AI Workbench」。保存成功后再关闭视频。

来源单独标为「YouTube 提问」，保留视频标题和链接，进入本地会话列表，支持复制、收藏及 Markdown / JSON 导出。无需模型 API，也不接通 YouTube 聊天。30 轮（60 条消息）的测试页面已验证读取、延迟加载及保存；当前用户账号页面仍待实测。不能恢复关闭页面前尚未保存、网页也已不再提供的记录。YouTube 未提供历史总数，读到边界也请核对首尾；停止或超时会标注部分记录。图像、视频卡片和交互测验的完整还原不在本次范围内。

[YouTube 官方说明](https://support.google.com/youtube/answer/14110396?hl=en)将视频提问与 Gemini 应用列为不同体验，本功能保存在工作台，不向 Gemini 历史写入。结构与验证边界见 [YouTube 适配记录](YOUTUBE_CAPTURE_NOTES.zh-CN.md)。

## 语音输入：工作台录音与本地识别

1. 点击输入框旁的「语音输入」→「开始录音」。
2. 默认开启「说完自动填入」：说完后安静约 2 秒，自动结束录音并在本机识别；也可点击「完成录音」立即识别。
3. 文字填入原草稿的光标 / 选中位置，检查后手动发送。需要边想边说、较长停顿或先试听时，关闭「说完自动填入」，恢复手动完成、试听和识别。此偏好会记住。

自动结束依据麦克风音量判断，环境持续嘈杂时可手动完成；连续 15 秒未检测到清晰说话声会停止并提示，不会自动识别空录音。识别失败保留录音供重试，模型未就绪时保留录音等待手动识别。

每次最多两分钟；取消、关闭或切换会话会停止录音。识别失败保留本次录音供重试；关闭面板会清理本次录音。录音仅在内存中，不写入聊天记录、不上传到语音服务。模型在独立 CPU 进程加载，完成、取消或超时后退出，释放识别内存。如果识别期间原草稿发生变化，会保留结果供手动追加，不覆盖新草稿。

已在本机准备 SenseVoice int8 中文 / 多语言模型。模型与词表 **239,549,735 字节**，Windows CPU 运行组件 **23,514,467 字节**，合计约 **263 MB（251 MiB）**。不需要语音 API、Python、PyTorch、CUDA 或显卡。模型就绪后录音和识别可离线使用；Windows 本身仍需允许工作台访问麦克风。

模型位于项目的 local-models/sensevoice，可在语音面板删除，之后按需重新下载。首次在其他电脑使用时，面板提供约 240 MB 下载；主站为 Hugging Face，主站不可达时回退到 HF 镜像，固定版本及 SHA-256 校验通过后才使用。取消下载会删除未完成文件，已校验文件保留以免重复下载。可通过 AI_WORKBENCH_VOICE_MODEL_DIR 指定模型保存位置。依赖按 package-lock 安装；模型不包含在源码或聊天 JSON 备份中。

验证：浏览器测试音源覆盖实际录音、试听、取消和草稿保护；作者公开中文样例已通过真正的本地模型及 Electron 进程完整识别、草稿回填。约 5.6 秒样例一次识别约 3.8～4.2 秒，此结果不代表任意长度、口音或噪声环境的性能。用户已确认自己的麦克风录音与识别可用；新版自动结束已通过公开音频测试，不同噪声环境仍可能需要手动完成。识别可能有错字，发送前应检查。组件来源见 [本地语音依赖说明](THIRD_PARTY_VOICE.md)。

## 图片发送与文字复制（桌面 v0.10.0 / 扩展 v0.9.0）

元宝、豆包网页账号聊天可在输入框 Ctrl+V 粘贴截图，或点击「添加图片」。发送前可预览、放大或移除；每次最多 3 张 PNG / JPEG / WebP，每张最多 2 MB。只有图片时会附上「请查看图片。」。发送的图片与消息一起保存在本机，重开后可查看，JSON 导出/导入保留图片；Markdown 导出内嵌图片数据，是否显示取决于阅读器。

请先重开工作台，在 Edge 的扩展管理页重新加载扩展至 v0.9.0，关闭旧连接页，再从元宝或豆包原对话重新连接。旧扩展仍可文字聊天，但图片发送会提示更新。原网页已有草稿/附件时先手动处理，保持网页与连接页打开。新图片先交给网页上传，确认出现预览且未显示上传状态后才提交；失败、无法确认或上传期间取消，不会降级为只发文字，也不会自动重发。真实网页可能更换上传结构，目前仍需用户实页验收。

各类消息提供「复制」按钮；可选中文字按 Ctrl+C，或右键复制。输入框右键支持粘贴、剪切、撤销和全选。此轮图片发送只接入元宝、豆包网页聊天；API 聊天仍为文本，历史扫描不补下载旧网页图片。

## 已实现

- 单聊中切换模型，带入当前分支的文本历史；可选择只发送本次问题。
- 多连接群聊并发回答；每个连接独立停止、失败、重试。重试保留原答案。
- 群聊默认使用公共提问和各模型自己的历史答案；通过发送目标或 `@连接名称 ` 单独追问。引用别人的回答会显式附加原文。
- 每条 API 回答记录连接、供应商、模型、状态、用量（服务返回时）和实际发送的上下文。
- 从已完成消息创建独立分支。
- 自动保存完整会话；重命名、文件夹、标签、全文搜索、归档和恢复。
- 左侧会话支持右键或「⋯」菜单：置顶 / 取消置顶、重命名、移动文件夹、分享、导出、归档 / 恢复、删除；有来源链接时可打开原网页。
- 分享提供 Markdown 预览、复制与文件导出，默认排除私人笔记和精选；不生成公开链接。删除前会显示消息及关联精选的范围，删除仅限本机，不修改网站原记录。
- 收藏完整回答或选中文字，附加标签与笔记，并回到原消息。
- 导出 Markdown 或 AI Workbench JSON；JSON 可导入会话与精选，导入不会带入密钥。
- 保存 Grok 等外部对话：粘贴原文、填写来源链接和“我的想法 / 项目草案”。原文按整体保留，不假装自动还原说话角色。
- 本地 SQLite 持久化；密钥使用 Electron safeStorage 的系统加密能力后保存。没有可用加密能力时拒绝保存密钥。

豆包接入流程见 [豆包使用与适配记录](DOUBAO_ADAPTER_NOTES.zh-CN.md)。在 Edge 更新同一个扩展后，在豆包原网页点击“连接豆包网页聊天”，再从工作台“网页账号 → 进入豆包网页聊天”使用。支持已加载历史同步、自动滚动、继续追问、收藏和导出；与元宝独立维护连接。真实豆包页面尚待首次验收。

在「网页账号」点击 **进入元宝网页聊天**。使用平时的浏览器登录元宝，在元宝标签页点击扩展 → **连接元宝网页聊天**，保持元宝和自动打开的连接页都不关闭；回到工作台即可输入问题并接回回答。

更新时先退出并重新打开工作台，在浏览器扩展管理页重新加载扩展。首次使用按下方配对说明操作。详见 [元宝使用说明](browser-extension/README.md#元宝网页聊天-v050-试用)。

第一版支持一条已绑定的元宝网页会话、文本发送、回答接回、左右排版、表格、收藏及 Markdown / JSON 导出。模型和历史沿用原网页设置。连接时快速读取网页已加载的历史；点击「自动加载并同步历史」后，会向上滚动加载旧记录，再向下检查到末尾，显示消息数量并支持停止。也可点「仅同步已加载」快速读取。按消息顺序与已有记录合并，保留消息 ID 和收藏；无法安全合并时，可另存为新会话。自动扫描最长 15 分钟，最多 1000 条消息 / 40 万字符；保持元宝网页可见，不要切换对话。页面不提供历史总数，即使检查到顶部、底部也不能保证服务器全部历史均已读取。原网页有草稿、生成中或连接失效时暂停发送。停止接收不会停止网页生成；断线和重启不自动重发问题。

用户已实际验证元宝连接、工作台提问和网页同步回答。新增历史同步已通过本地模拟验证，真实历史合并仍待用户复测；不保证所有账号、模式和页面版本都能适配。

## Gemini / X 内 Grok 网页账号（无需 API）

当前开发版提供「网页账号」入口。通过本地 Chrome / Edge 扩展，逐段滚动加载、预览并保存你当前打开的 Gemini 或 X 内 Grok 对话，来源链接和笔记一同进入会话列表。

打开应用的「网页账号」页，按三步说明加载 browser-extension 文件夹并配对。通过网页账号继续聊天仍在对应服务的原网页进行；不是实时镜像、全量账号同步或网页群发。浏览器保持你的登录状态，本软件不复制密码或 Cookie。

详细说明见 [浏览器扩展安装与使用](browser-extension/README.md)。自动化已验证本地接收与显示；用户已反馈 X 内 Grok 可读取 34 条消息，普通表格基本正常。其他会话仍需核对首尾、角色和内容完整性。

## 真实模型连接

在“连接与设置”中添加 DeepSeek API Key，模型 ID 可修改为你账号实际可用的型号。支持 Gemini 的兼容接口预设及自定义 OpenAI 兼容 Chat Completions 接口。基础地址由适配器自动追加 `/chat/completions`。

“测试连接”会发送一条短请求并使用少量 API 额度。群聊按每个连接分别调用。当前不估算金额，也不把缺失用量当成零。

**自动化验收使用本地 HTTP 测试服务，未使用你的真实密钥。用户已实际试用 DeepSeek；其他供应商的真实接入仍需分别验证。首次配置时，请在应用设置页填写自己的密钥。**

API 接口与网页产品是不同的连接：
- 尚未实现元宝、豆包、ChatGPT、Gemini 四家网页账号的一键群发。
- 已支持主动读取当前 X 内 Grok 对话；尚未实现全量账号历史自动同步、独立 grok.com 适配或第三方导出格式解析。也支持粘贴原文及导入本应用自己的 JSON。
- 尚未实现 Claude Code + DeepSeek 的工具桥接，也未新增 Claude 模型要求。
- WorkBuddy、豆包工作保留为后续扩展。
- API 聊天当前处理文本；元宝、豆包网页聊天支持图片。文档附件、跨模型自动讨论、自动项目草案生成和安装包尚未实现。

## Grok 对话沉淀

1. 点击左侧“保存外部对话”。
2. 粘贴有价值的讨论原文，保留原有提问和回答标记。
3. 保存 X 原帖、Grok 对话的链接，以及讨论产生的项目想法。
4. 之后可以搜索原文、收藏片段、补充笔记，或导出带来源的 Markdown。
5. 如选择 API 连接继续讨论并勾选“携带历史”，导入原文会明确作为用户提供的外部资料发送。

仅粘贴和保存不调用云端模型；来源链接只存储，不自动访问。

## 本地数据

默认保存位置：

```text
%APPDATA%\AI-Workbench\workbench.sqlite
```

聊天数据独立于源码目录；修改 `AI-Workspace` 的名称不会改变数据位置。设置页显示实际路径。密钥经系统加密保存，拷到其他系统或用户下可能无法解密，届时需重新填写。

使用 JSON 会话导出进行内容备份；如复制整个数据库目录，请先完全退出应用，并一起保留同目录内的 SQLite 相关文件。

开发或测试可用 `AI_WORKBENCH_DATA_DIR` 指定独立目录。测试自动使用临时目录，与个人数据隔离。

## v0.4.1：存档阅读与表格收藏

- 存档中的独立发言者标记（例如单独一行“我：”“Grok：”）显示为你在右、助手在左；没有可靠标记的原文保留中性显示，不猜测身份。
- 已有记录中至少三列、表头加至少两行且列数一致的竖线表格，会尝试恢复为表格。可切换“查看原始文本”；存储、发送上下文与导出仍使用原文。
- 表格支持横向滚动。选中一张表格内的文字再收藏，将保留整张表格及表头；收藏预览和精选库也显示表格。
- Grok 扩展 v0.4.3 在读取 HTML 表格时生成 Markdown 表格，保留单元格换行和链接；合并单元格展开为普通网格，合并区域其余格留空。
- 更新后退出并重开工作台。在浏览器扩展管理页重新加载扩展，再刷新 X 的 Grok 对话页。旧存档的显示修复直接生效；缺失的原始格式或发言者信息需要重新提取。

## v0.4.2：Markdown 代码块阅读与复制

代码块右上角新增复制按钮，复制保存的完整代码块正文，不包含外层围栏；阅读和源码视图使用同一份正文。Markdown / md / mdown 代码块默认渲染标题、列表和表格，可切回源码。旧的无语言标记代码块会依据明确 Markdown 特征自动进入阅读，也可手动点“阅读”；明确标为 Python 等语言的代码保持源码显示。

预览中的表格仍可收藏，收藏取自原始内容。正文、上下文和导出不因阅读视图而被重写；不执行代码或原始 HTML。嵌套 Markdown 预览最多三层，避免递归展开过深。

重启工作台即可使用现有记录。扩展 v0.4.6 补充代码块语言标记保留；在扩展管理页重新加载并刷新 Grok 页面后，新提取会带上原网页提供的语言标记。
